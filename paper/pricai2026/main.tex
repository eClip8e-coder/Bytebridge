\begin{abstract}
Subword tokenizers are efficient input interfaces for common text, but they can be brittle on typos, Unicode text, code, multilingual text, and unusual strings. Byte-level models avoid fixed vocabularies when trained from scratch, but many useful language models already exist with fixed tokenizers. We ask whether such a model can be kept frozen and given an input-side byte interface through only a small trainable adapter. ByteBridge tests this question with a paired protocol: input context is derived from bytes, target tokens remain native, and the LM backbone and head stay frozen. On Qwen2.5, a ladder from input-layer byte patches to KV-prefix memory improves typo-noise robustness but does not match native tokenization on clean or non-typo stress inputs. On TinyLlama, the deeper KV interface is stronger and can outperform native tokenization on clean, typo, Unicode, and multilingual buckets when multilingual examples are included in training, while tokenizer-stress strings remain difficult. Together, these results identify a practical limit of byte-side retrofitting: frozen tokenizer-based models do not merely consume embedding vectors, but also depend on token units, boundaries, and positions induced during pretraining.

\keywords{Tokenization \and Byte-level modeling \and Frozen language models \and Adapter tuning \and Diagnostic study}
\end{abstract}

\section{Introduction}

Subword tokenizers are the front door of most language models. They turn raw text into the discrete units that the model was trained to read. This works well for common text, but it can be brittle. A small typo may change the segmentation. Rare Unicode characters may become many tokens. Code, file paths, long identifiers, and multilingual text may be split in ways that look different from clean English.

Byte-level modeling avoids out-of-vocabulary inputs because every string can be written as bytes. Recent byte, character, and adaptive-tokenization models improve coverage, robustness, multilingual segmentation, and efficiency when trained for this format from the beginning \cite{ahia2024magnet,clark2022canine,kallini2025mrt5,pagnoni2025byte,slagle2024spacebyte,tay2022charformer,xue2022byt5,yu2023megabyte}. But many useful language models are not byte models. They were trained with a fixed tokenizer. A tempting shortcut is to keep such a model frozen and train only a small adapter that turns input bytes into continuous vectors the model can use.

This paper tests that shortcut. We ask: \emph{can a small byte adapter give useful input context to a frozen tokenizer-based language model, without badly hurting clean-text performance?} We study this with \bb{}, primarily on Qwen2.5 causal language models \cite{qwen2024technical}, with a selected TinyLlama replication \cite{zhang2024tinyllama}. The language-model backbone, input embedding table, and LM head are always frozen. Only byte-side adapters are trained. The output side still uses each model's native tokenizer, so this is not a fully tokenizer-free language model. It is a test of whether the \emph{input side} of an existing tokenizer-based model can be replaced or augmented by bytes.

There are two plausible outcomes. The optimistic view is that a byte adapter can map UTF-8 bytes into vectors that a frozen model can use, especially if those vectors are aligned to token embeddings or inserted through prompt- or prefix-tuning interfaces \cite{lester2021prompttuning,li2021prefixtuning}. The pessimistic view is that a tokenizer-based model learns tokenizer-induced structure beyond token embeddings: units, boundaries, positions, and attention patterns. A small adapter may not recover all of that structure.

We evaluate these possibilities with a diagnostic ladder. We first test input-side byte interfaces at the input layer, then alignment and reconstruction objectives, and finally deeper byte-derived memory through soft-prefix and per-layer KV-prefix injection. The same evaluation suite is reused throughout: clean English, typo noise, Unicode stress, multilingual text, code, and tokenizer-stress strings.

The main result is mixed. On Qwen2.5, byte adapters consistently beat the native tokenizer baseline on typo-noise prompts, but every byte adapter is worse on clean text, and the native tokenizer remains better on Unicode, code, and tokenizer-stress inputs. Deeper byte-derived memory helps: all-layer KV-prefix gives the best \qwen{} clean retention, $1.61\times$ the tokenizer baseline, but still misses our $1.5\times$ diagnostic threshold. On \tinyllama{}, the same all-layer KV-prefix interface is much stronger: over three seeds it beats the tokenizer baseline on clean, typo-noise, and Unicode buckets. A multilingual training ablation then shows that the severe held-out multilingual failure is not intrinsic to byte input, but depends on coverage and model family. This cross-family contrast is the central finding: byte adapters can help, but they are not a general drop-in replacement for the tokenizer-induced structure that the frozen model was trained to use.

This paper makes four contributions. 1) We build a paired benchmark and scoring protocol for byte-side input adapters with fixed target-token evaluation. 2) We compare input-layer byte patches, alignment and reconstruction objectives, soft prefixes, and all-layer KV-prefix memory, showing that deeper injection helps but does not close the Qwen2.5 clean-retention gap. 3) We add preprocessing controls, fragmentation analysis, cross-model replications, and a train-only multilingual ablation to separate cleanup, fragmentation, model-family, and coverage effects. 4) We report a mixed result: Qwen2.5 adapters mainly improve typo robustness, while TinyLlama KV-prefix adapters are stronger and more coverage-sensitive.

\section{Problem Setting}

Let $M$ be a pretrained causal language model with tokenizer $T$, input embedding matrix $E$, transformer $F$, and LM head $H$. In all experiments, $E$, $F$, and $H$ are frozen. Given an input string $x$ and target string $y$, the native tokenizer baseline computes
\begin{equation}
    \loss_{\mathrm{tok}}(x,y) = - \sum_t \log p_M(y_t \mid T(x), y_{<t}),
\end{equation}
where $y_t$ are target tokens under the model's tokenizer. Byte variants replace or augment the conditioning on $x$ with continuous states $A(b(x))$. Here $b(x)$ is the UTF-8 byte sequence and $A$ is the trainable adapter. The target side remains tokenized. This keeps the comparison fair: every system is scored on the same target tokens.

This paired conditional setup is important. Comparisons can be misleading if one system is scored on bytes and another on tokens, or if noisy inputs change the supervised target. We avoid that problem by keeping $y$ fixed. For noisy examples, $x$ is the perturbed string and $y$ is the clean target suffix. Loss is computed only over target tokens, not over byte-prefix or adapter positions.

The main metric is per-bucket target-token loss. We also save perplexity in the experiment artifacts, but focus on loss because stress-bucket perplexities can be very large. To measure clean-text degradation, we use
\begin{equation}
    \cratio(A) = \frac{\loss_A(\mathrm{clean})}{\loss_{\mathrm{tok}}(\mathrm{clean})}.
\end{equation}
Before running the diagnostic ladder, we set two practical thresholds: adapters with at most 50\% higher clean loss than the tokenizer baseline are treated as diagnostically promising ($\cratio \leq 1.5$), and adapters with at most 20\% higher clean loss are treated as strong ($\cratio \leq 1.2$). These thresholds are diagnostic guardrails, not tuned decision boundaries. They prevent us from calling a byte interface useful when it only wins narrow stress cases by sacrificing clean text.

For key bucket comparisons, we also run paired bootstrap over test examples. Each resample draws examples with replacement within a bucket and recomputes the mean difference in loss, byte adapter minus tokenizer baseline, over 10,000 resamples. A negative difference means the byte adapter has lower loss.

\section{Benchmark and Metrics}

We construct a small, reproducible suite that stresses tokenizer-unfriendly inputs while remaining feasible in a single-GPU setting. The train, validation, and test manifests are fixed after construction and reused across all phases; test examples are never used for training. Each record stores its bucket, text fields, source, perturbation metadata, seed, and clean-example identifier where applicable.

Buckets are generated from predefined rules and fixed seeds, not selected after observing model outcomes. Typo variants stay within their original split, train and test share no clean-example identifier, and all released manifests keep source and perturbation metadata. The suite is not a traffic model, but the comparisons are auditable.

The test buckets are:
\begin{itemize}
    \item \textbf{Clean English}: short natural-language, Wikipedia-like, instruction-like, and QA-like snippets.
    \item \textbf{Typo noise}: clean English with random deletion, insertion, substitution, adjacent swaps, repeated characters, whitespace perturbations, and casing noise at light, medium, and heavy levels.
    \item \textbf{Unicode stress}: emoji, accented characters, combining marks, zero-width joiners, full-width characters, mathematical symbols, punctuation variants, and normalized or non-normalized mixtures.
    \item \textbf{Multilingual text}: short Chinese, Japanese, Korean, Arabic, Hindi, Russian, and Latin-script accented examples.
    \item \textbf{Code}: Python, JavaScript, JSON, shell commands, stack traces, regular expressions, SQL, and configuration snippets.
    \item \textbf{Tokenizer-stress strings}: URLs, file paths, package names, UUIDs, base64-like and hexadecimal strings, logs, long identifiers, and mixed separators.
\end{itemize}

\section{ByteBridge Adapter Family}

\subsection{Input-Layer Byte Latents}

The simplest adapter groups bytes into fixed-size patches and maps them into $L$ prompt vectors in the LM hidden dimension. This directly replaces tokenized prompt embeddings through \texttt{inputs\_embeds}. We train clean-only and noise-augmented variants; the strongest Phase 2 run uses $L=32$ and 2000 noise-augmented steps.

\subsection{Embedding Distillation}

One possible failure is that byte latents are far from Qwen token embeddings. We therefore pretrain the adapter with fixed token-span alignment or pooled sequence alignment against frozen token embeddings, then fine-tune it with the same frozen-LM conditional objective.

\subsection{Token Reconstruction and Boundary-Aware Patching}

Embedding MSE may be too weak if the frozen model needs token-like identity rather than nearby vectors. We map tokenizer tokens to UTF-8 byte spans and pretrain byte/span latents to predict tokenizer token IDs. We test fixed patches, heuristic tokenizer-free boundaries, and oracle tokenizer-derived spans. The oracle mode is a diagnostic upper bound, not a tokenizer-free method; the classifier head is discarded before LM evaluation.

\subsection{Soft Prefix Injection}

Input replacement may be too strict because it forces byte latents to behave like token embeddings at prompt positions. Soft prefix injection instead compresses input bytes into $P$ learned prefix embeddings, concatenates them before tokenized target embeddings, and computes loss only on target positions:
\begin{equation}
    \mathrm{inputs\_embeds} = [A_{\mathrm{prefix}}(b(x)); E(T(y_{<t}))].
\end{equation}
This keeps native target-side teacher forcing while giving the frozen model byte-derived context.

\subsection{KV-Prefix Injection}

Finally, we test deeper injection by inserting byte-derived prefix memories into attention key/value inputs. For Qwen's \texttt{DynamicCache}, these memories have shape $[B,H_{kv},P,d_h]$. We test first-4-layer and all-layer injection; non-injected layers receive zero K/V tensors of the same prefix length for cache consistency. This is a diagnostic compromise, not an optimal prefix-tuning design.

\subsection{What Each Diagnostic Tells Us}

\paragraph{Fixed Byte Patches Are Insufficient.}
The Phase 2 input-layer adapter confirms engineering feasibility: gradients flow through \texttt{inputs\_embeds}, LM trainable parameters remain zero, and checksum drift is zero. But its best clean retention is only $2.19\times$, with severe degradation on Unicode, code, multilingual, and tokenizer-stress buckets.

\paragraph{Embedding Alignment Is Not Enough.}
Projection alignment works as an auxiliary objective: distillation loss drops from $0.9583$ to $0.0637$ for $L=32$ and from $0.9654$ to $0.0752$ for $L=64$. Downstream LM evaluation does not improve: the $L=32$ distill-then-LM run has $2.22\times$ clean retention. Matching token embeddings geometrically is therefore not enough.

\paragraph{Token Identity Is Learnable, but Not Sufficient.}
Token reconstruction is stronger than embedding alignment. Fixed reconstruction reaches validation clean top-1 accuracy $0.8669$, and oracle-boundary reconstruction reaches $0.9945$. Yet downstream clean retention remains poor: fixed reconstruction improves to $1.84\times$, while oracle-boundary reconstruction is $2.20\times$. Boundary and identity errors are real bottlenecks, but not the only bottlenecks.

\paragraph{Deeper Injection Helps, but Not Enough.}
Soft prefix and KV-prefix variants test whether the frozen model needs byte information as attention context rather than replacement input embeddings. The answer is partially yes: soft prefix p64 improves code, Unicode, and tokenizer-stress losses over input-layer variants, and all-layer KV-prefix gives the best clean retention, $1.61\times$. But neither reaches $1.5\times$ clean retention, and neither beats the tokenizer baseline on non-typo stress buckets.

\section{Mechanism Analysis}

\subsection{Fragmentation Correlates with Loss, but Does Not Explain Everything}

Tokenizer-unfriendly strings often produce longer token sequences. We measure several fragmentation proxies on the fixed test set: input byte length, input token length, tokens per byte, and bytes per token. We then correlate these with tokenizer loss and with byte-adapter gain over the tokenizer baseline.

Table~\ref{tab:frag} gives selected correlations. Input token length has a strong Pearson correlation with tokenizer loss ($0.669$) but a much weaker Spearman correlation ($0.214$), meaning length is useful but not a complete ranking signal. Tokens per byte has a smaller Pearson correlation ($0.227$) and a moderate Spearman correlation ($0.334$). Byte adapters gain more on longer tokenized inputs, with Spearman correlations of $0.459$ for soft prefix p64 and $0.477$ for KV-prefix p32 all-layer. Still, high fragmentation is not enough to predict success. Without multilingual adapter training, multilingual buckets are highly problematic even though byte input should, in principle, avoid vocabulary coverage issues. \subsection{Interpretation}

The diagnostics narrow the failure mode. Embedding alignment, oracle token boundaries, and deeper prefix injection each help only partially. If the issue were only embedding geometry, boundary segmentation, or shallow input injection, one intervention should have closed the clean-retention gap. None did.

Our interpretation is that frozen tokenizer-based language models depend on several parts of tokenizer-induced structure at once. Native token embeddings carry local text content, but the model also expects familiar token units, boundary lengths, position steps, and attention patterns. A small input-side byte interface trained after the fact can learn useful robust cues, especially for typo-noise denoising, but it does not recreate the full input interface.

The multilingual ablation in Section~8.1 refines this point. When multilingual text is absent from adapter training, held-out multilingual buckets fail catastrophically. Adding multilingual training examples largely removes that failure for TinyLlama, but Qwen still pays a large clean-retention cost. The issue is therefore not byte representation alone; it is coverage, capacity, and compatibility with the frozen model's tokenizer-induced interface.

\section{Cross-Model Replication}

To test whether the Qwen result is model-family specific, we run selected replications on two additional frozen models. This is not a full rerun of the entire diagnostic ladder. It is a focused check of the best later-stage interfaces: soft prefix p64 and all-layer KV-prefix p32.

The first replication uses \qwena{}. This keeps the tokenizer family and cache API close to the primary model, reducing engineering confounds while testing a larger frozen Qwen2.5 model. The native \qwena{} tokenizer clean loss is $0.3274$. Soft prefix p64 improves with longer training, from $6.22\times$ clean retention at 2000 steps to $2.73\times$ at 8000 steps, but remains far above the $1.5\times$ threshold. All-layer KV-prefix is the best selected \qwena{} run, with $2.52\times$ clean retention. It beats the tokenizer baseline only on medium and heavy typo noise.

The second replication uses \tinyllama{}, which changes the tokenizer and model family. Here the result is different. The native tokenizer clean loss is $0.6026$. Soft prefix p64 reaches $1.26\times$ clean retention and beats the tokenizer baseline on all three typo buckets. All-layer KV-prefix p32 is much stronger: across three seeds, its mean clean retention is $0.63\times$, and the seed values are $0.69$, $0.66$, and $0.55$. The three-seed mean beats the tokenizer baseline on clean English, all typo buckets, and Unicode stress, while losing on tokenizer-stress and on multilingual buckets that were absent from adapter training. Paired bootstrap confirms these signs: 95\% intervals do not cross zero for the clean, typo, and Unicode gains, or for the tokenizer-stress and held-out multilingual losses. A target-only sanity baseline has clean loss $5.4014$, and a learned constant KV-prefix that never reads input bytes has clean loss $0.8907$. These controls show that target-side prediction and generic soft prompting do not explain the full TinyLlama KV result.

\subsection{Interpreting the TinyLlama-Qwen Gap}

The TinyLlama result changes the interpretation, but not the caution. Qwen shows that byte adapters are not reliable drop-in replacements: even all-layer KV-prefix misses the clean-retention threshold and never beats the tokenizer outside typo noise. TinyLlama shows the other side of the boundary: the failure is not universal, and some frozen models can use byte-derived KV memory better than their tokenized prompt.

We do not identify a single cause for the TinyLlama-Qwen gap. Two clues are useful but incomplete. TinyLlama's native tokenizer baseline is weaker on this benchmark, with clean loss $0.6026$ rather than Qwen2.5-0.5B's $0.3089$. It also tokenizes the same inputs more densely, with higher input tokens per byte on clean text ($0.241$ vs. $0.218$), Unicode ($0.493$ vs. $0.383$), code ($0.533$ vs. $0.453$), tokenizer-stress strings ($0.700$ vs. $0.584$), Chinese ($0.550$ vs. $0.318$), and Arabic ($0.547$ vs. $0.286$). This may leave more room for byte-conditioned KV memory, but fragmentation is not sufficient: TinyLlama's multilingual inputs are also highly fragmented, yet byte KV fails when these scripts are absent from adapter training.

Training curves rule out a stalled optimizer: Qwen2.5-0.5B drops from training loss $8.61$ to $0.25$, and the three TinyLlama seeds drop from $10.36/11.28/10.76$ to $0.21/0.30/0.22$. The gap appears in validation and test behavior. TinyLlama reaches validation clean losses of $0.30$--$0.39$, while Qwen reaches $0.468$. A constant TinyLlama KV-prefix that does not read input bytes has test clean loss $0.8907$, so the TinyLlama gain is not just target-side prediction, generic soft prompting, or optimizer success.

We also compare each learned byte KV cache with the native cache produced by tokenized prompts. This does not support the simple idea that TinyLlama works because its byte KV tensors are globally closer to native KV tensors. Qwen's byte-to-native key/value RMS ratios are $0.69/3.12$, while TinyLlama's are $1.61/19.26$. TinyLlama has only slightly higher mean-vector cosine ($0.071/0.039$ for key/value, versus Qwen's $0.021/-0.032$). The result points instead to a sensitivity difference: TinyLlama can use some high-magnitude byte-derived prefix memory, even though that memory is not a faithful copy of its native prompt cache.

The multilingual failures in Table~\ref{tab:tinyllama-buckets} are held-out failures: the adapters were trained on clean English, typo noise, Unicode, code, and tokenizer-stress buckets, but not on multilingual buckets. To test whether this is an intrinsic byte-interface failure or a coverage failure, we add a train-only multilingual supplement of 1120 examples, 160 for each of seven language groups, and keep the validation and test manifests unchanged. \section{Related Work}

\paragraph{Subword Tokenization.}
Subword tokenizers such as byte-pair encoding, WordPiece, and SentencePiece are widely used because they balance vocabulary size and open-vocabulary coverage \cite{devlin2019bert,kudo2018sentencepiece,sennrich2016neural}. Prior work has shown that tokenization choices affect robustness, fairness, multilingual efficiency, language variation, byte-level probabilities, and token-level vulnerabilities \cite{ahia2024magnet,jang2025improbable,mielke2021between,phan2025exact,rust2021good,wegmann2025tokenization}. \bb{} focuses on a complementary question: whether an already-tokenized language model can be retrofitted with a byte-based input side while keeping the model frozen.

\paragraph{Byte and Character-Level Language Models.}
Byte and character models show that raw input units can work when the model is trained for them \cite{clark2022canine,kallini2025mrt5,pagnoni2025byte,slagle2024spacebyte,tay2022charformer,xue2022byt5,yu2023megabyte}. Figure~\ref{fig:related} summarizes why these are not direct baselines for our frozen-adapter setting.

\paragraph{Parameter-Efficient Frozen-Model Adaptation.}
Prompt tuning, prefix tuning, and LoRA show that frozen or mostly frozen LMs can be steered by small trainable modules \cite{hu2022lora,lester2021prompttuning,li2021prefixtuning}. Our task is different: the trainable module must encode the raw input string itself from bytes, not only provide a task prompt. This is why we include a constant-prefix control.

\paragraph{Diagnostic Negative and Mixed Results.}
\bb{} is a diagnostic study of when a tempting shortcut fails or works only under narrow conditions. Embedding alignment, oracle boundary reconstruction, and deeper prefix injection are each insufficient for reliable Qwen2.5 byte adapters. TinyLlama adds the complementary lesson that the failure is not universal.

\section{Limitations}

This study is scoped to Qwen2.5 and TinyLlama, small adapters, a single-GPU environment, and a synthetic or curated stress benchmark. The suite is for controlled diagnosis, not for estimating real-world frequency or user impact; real text may contain different noise patterns, longer contexts, mixed tasks, and domain-specific conventions. The typo gains should therefore be read as evidence that byte adapters can use noisy byte cues under this paired benchmark, not as a deployment claim about all user typos.

We do not claim that all byte interfaces for all frozen LMs must fail, or that TinyLlama's success transfers to other model families. We also do not eliminate the target-side tokenizer: supervision and output scoring use each model's native target tokens for fair comparison. The study has not tested many tokenizer families, substantially larger adapters, longer schedules, contrastive pretraining, hard negatives, or partial LM finetuning. Oracle-boundary reconstruction uses tokenizer-derived boundaries and is a diagnostic upper bound; first-$N$ KV-prefix variants use zero K/V tensors for non-injected layers to maintain cache length consistency, which may not be optimal.

\section{Conclusion}

\bb{} asks whether a small input-side byte interface can replace or augment native tokenized input for a frozen tokenizer-based language model. The answer is mixed. Under Qwen2.5, byte adapters produce a consistent typo-noise robustness signal and deeper byte-derived memory improves several stress categories, but clean retention remains too poor and native tokenization continues to dominate non-typo stress buckets. Under \tinyllama{}, all-layer KV-prefix injection is much stronger and beats native tokenization on clean, typo, and Unicode buckets; with multilingual training, it also beats the tokenizer on multilingual buckets, but tokenizer-stress remains difficult. Deterministic preprocessing controls do not explain away the typo signal, and fragmentation analysis shows only a partial mechanism. The main lesson is that tokenization induces input structure that a byte adapter must recover or replace.
